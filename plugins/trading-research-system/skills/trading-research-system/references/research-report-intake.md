# Research Report Intake

Use this reference when finding, ingesting, summarizing, or validating research reports and research-style articles.

The goal is not a long summary. The goal is a compact, verified decision note that can feed `Industry/Sector Strength`, `Company Thesis Check`, the Cross-Section Candidate Pool, or an Active Market Plan update.

## Source Priority

Use source priority before accepting a claim:

| Level | Examples | Best Use | Limitation |
| --- | --- | --- | --- |
| S0 official / primary | SEC filings, earnings releases, company IR decks, conference call transcripts, official macro data | company facts, guidance, segment data, official policy or macro facts | may still require interpretation |
| S1 market data / broker / macrodata / calendar | authorized prices, yields, macrodata, volume, options data, earnings calendars | current macro/market confirmation and event timing | not a thesis by itself; policy facts still need S0 |
| S2 reputable financial media | Reuters, AP, Bloomberg, WSJ, FT, CNBC, MarketWatch | news leads, reported context, management or policy quotes | verify market-moving claims with S0/S1 when possible |
| S3 research / opinion | Seeking Alpha, sell-side notes, independent research, Substack, newsletters | thesis generation, counterarguments, valuation framing | not proof of policy, company facts, or current data |
| S4 social / rumor | X, Reddit, forums, unsourced commentary | usually ignored | only useful if confirmed by stronger sources |

## Discovery Mode

When asked to find reports:

1. Search for public, authorized, or user-accessible reports and research-style sources.
2. Prefer recent sources unless the user asks for historical thesis evolution.
3. Collect opposing views, not only confirmation.
4. Rank sources by relevance, freshness, author/source quality, and direct usefulness for the current watchlist or plan.
5. Stop before paywall bypass. If a useful source is inaccessible, report it as inaccessible and ask the user to provide it or authorize a source.

Discovery output should include:

- source title;
- source type and priority;
- date;
- target ticker/theme;
- stance;
- why it is worth reading;
- what it could change in the plan;
- access status: public / user-provided / inaccessible.

## Intake Mode

When the user provides a PDF, link, excerpt, screenshot, or copied text:

1. Identify source, author, publication date, covered ticker/theme, stance, rating, price target, and horizon when available.
2. Extract the core thesis in one or two bullets.
3. Extract counter-thesis and what would make the report wrong.
4. Separate facts from estimates, author opinion, and assumptions.
5. Note data dates. Flag stale data, old estimates, and missing context.
6. Map the report to `Industry/Sector Strength`, `Company Thesis Check`, or neither.

## Research Report Digest

Use this shape for the final compact note:

| Field | Content |
| --- | --- |
| source | title, author/source, date, access status |
| target | ticker/theme, stance, horizon |
| thesis | the strongest version of the report thesis |
| counter_thesis | the strongest opposing view |
| evidence_quality | strong / medium / weak, with why |
| current_relevance | current / partly stale / stale |
| plan_impact | supports / pressures / blocks / watch only |
| next_check | the next source or market confirmation needed |

## Claim Ledger

For material claims, record:

| claim | type | report evidence | verification source | status | plan impact |
| --- | --- | --- | --- | --- | --- |
|  | fact / estimate / opinion / assumption |  | S0/S1/S2/S3 | verified / needs_check / contradicted / stale | supports / pressures / blocks / none |

The Claim Ledger should favor fewer, important claims. Do not fill it with every sentence.

## Verification Queue

The Verification Queue is the list of checks before the report can affect a trade plan:

- filings, earnings releases, investor decks, and transcripts for company facts;
- official macro sources for policy, inflation, labor, Treasury, and Fed claims;
- current market data for price, valuation, yields, spreads, volatility, and relative strength;
- counter-research or disconfirming data;
- event calendar checks for earnings, product events, regulatory deadlines, and macro releases.

## Trade Plan Preparation Impact

Convert the report into plan-preparation language:

- `Industry/Sector Strength`: sector leadership, breadth, cycle, demand, policy beneficiaries/losers, relative strength.
- `Company Thesis Check`: verified thesis/counter-thesis, valuation, catalyst, guidance, balance sheet, and disconfirming facts.
- `Cross-Section Candidate Pool`: only add a ticker/theme when the report changes research priority and the next check is concrete.
- `Setup Pool`: do not promote directly. Promotion still requires higher-timeframe environment, price structure, trigger zone, invalidation, risk context, and next check.

## Copyright Boundary

Do not bypass paywalls or access controls. Do not reproduce long copyrighted passages. Summarize in your own words, quote only short evidence snippets when necessary, and ask the user to provide authorized content if a report is not accessible.
