# v1.0.2：轻量运行包与分层个股研究

## Problem Statement

作为 Mars Research Assistant 的使用者，我希望安装和运行的是一个完成明确投研任务的轻量 Skill
包，而不是一个在安装时下载并执行 shell、预建大型 Python 环境、混合开发文件与运行文件的仓库
副本。当前单一“标的研究”同时承担快览与深度研究的预期，导致普通问题的任务边界、运行成本和
输出深度不稳定；同时纯聊天式文字交付难以复查、归档或可靠地传递给后续步骤。

我需要能通过常规 Skills CLI 安装 Mars Research Assistant，在默认情况下快速获得有来源、带
`as_of` 和数据缺口的个股快览；只有明确需要估值、财报复盘、竞争格局或建模时才进入深度研究。
无论调用哪个文字型能力，我都需要在自己的活动工作目录中得到不覆盖旧文件的 Markdown 源稿，
而不是仅在聊天中看到不可审计的长文本。

## Solution

将 Mars Research Assistant 分发为一个独立、最小的运行包，并以 Skills CLI 作为唯一公开安装
路径。运行包包含根入口、七个子 Skill、运行期脚本、锁文件和必需内置资源；开发测试、文档、
README、仓库元数据和预建环境留在开发仓库中。技术面分析保留其按需 Python 环境，但只在首次
真实技术面请求时初始化。

将个股研究拆为两个具有明确路由规则的子 Skill。个股快览保持稳定机器标识
`instrument-research`，在发行人身份核验后交付三项带 `as_of` 的关键公开数据、30 天内 3–5 条
直接相关公司公告或新闻、来源、时间戳与数据缺口。深度个股研究使用
`deep-equity-research`，提供固定九章、跨市场财报质量核查，以及只在来源可追溯输入完整时才
运行的三情景 DCF/反向 DCF。

所有文字型交付都创建活动工作目录 `mars-research/` 下的唯一 Markdown 工件。PDF 或 PowerPoint
只在用户明确要求或视觉表达确有显著增益时额外生成；Drive 写入仍是独立确认后的操作。

## User Stories

1. As a Codex user, I want to install Mars Research Assistant with the standard Skills CLI, so that I do not need to execute a downloaded shell installer.
2. As a user, I want the installed package to contain only runtime material, so that tests, documentation, repository metadata, and prebuilt environments do not consume my Skill installation.
3. As a user, I want installation to avoid preparing technical-analysis dependencies up front, so that non-technical research starts quickly.
4. As a technical-analysis user, I want the isolated dependency environment to be prepared only when I first request that capability, so that its requirements do not burden the other six Skills.
5. As a user asking a vague company question, I want Mars to default to a quick company snapshot, so that ordinary research remains lightweight.
6. As a user requesting valuation, modelling, earnings review, competition analysis, or an investment memo, I want Mars to route me to deep equity research, so that the report depth matches my stated intent.
7. As an existing Mars user, I want the quick-research machine identifier to remain `instrument-research`, so that my existing direct invocations remain compatible.
8. As a user, I want deep equity research to have its own machine identifier, so that I can explicitly request the heavier workflow.
9. As a user, I want Mars to verify the company name, ticker, exchange, and issuer before research begins, so that I do not receive a report about the wrong company.
10. As a user with an ambiguous ticker or issuer, I want Mars to request clarification and create no artifact, so that uncertain identity is never disguised as research.
11. As a quick-snapshot user, I want price, market scale or valuation anchor, and latest financial summary to be dated and sourced, so that I can judge freshness and provenance.
12. As a quick-snapshot user, I want three to five company-direct announcements or news items from the last 30 days, so that the update is timely without becoming a broad news dump.
13. As a research user, I want missing or conflicting public information called out explicitly, so that I can distinguish absent evidence from a negative conclusion.
14. As a deep-research user, I want a stable nine-chapter report structure, so that I can compare companies and find evidence consistently.
15. As a deep-research user, I want financial-quality checks that work across markets, so that the report does not imply false precision from US-specific scoring models.
16. As a deep-research user, I want each financial-quality finding to have a source or a declared gap, so that I can audit the conclusion.
17. As a valuation user, I want DCF calculations to require a source-traceable assumption set, so that unavailable values are not silently invented by the model.
18. As a valuation user, I want missing price, share count, net debt, WACC, terminal growth, or scenario free-cash-flow inputs to skip valuation cleanly, so that incomplete evidence does not produce a misleading number.
19. As a user, I want research conclusions to state risks, counter-theses, and falsification conditions without turning into buy, sell, position-size, or order instructions, so that research remains decision support rather than trade execution.
20. As a user, I want every textual final deliverable to be saved as a unique local Markdown source file, so that I can read, retain, compare, and archive it outside the chat.
21. As a user, I want PDF and PowerPoint to remain optional visual supplements, so that a simple request does not incur unnecessary rendering work.
22. As a Drive user, I want a local Markdown proposal or receipt in addition to the separate Drive confirmation flow, so that cloud actions remain reviewable and do not replace local evidence.
23. As a maintainer, I want a single high-level offline verification entry point, so that package boundaries, research contracts, artifact behavior, and performance budgets can be checked together.
24. As a maintainer, I want a measurable package-size, file-count, install-stage, and fixture-render budget, so that “lightweight” remains an enforceable property rather than an aspiration.

## Implementation Decisions

- The public unit remains one Mars Research Assistant combination Skill with seven internal child Skills: Ask Mars, market catalysts brief, market snapshot, equity snapshot, deep equity research, technical analysis, and Drive writeback.
- The root entrypoint uses the approved Skills CLI installation command and explains that it copies the complete runtime package. It does not offer a downloadable shell-based installation path or a custom npm CLI.
- The runtime package is physically separated from development material. It contains only the root entrypoint, child Skills, runtime scripts, lock metadata, and mandatory vendored resources; it excludes tests, human-facing repository documentation, repository metadata, and any prebuilt virtual environment.
- The original individual-company capability remains reachable through `instrument-research` but is presented to users as “个股快览”. The new deep workflow uses `deep-equity-research`.
- Root routing uses explicit user intent. A single-stock request defaults to equity snapshot unless the request explicitly signals deep research, valuation, earnings review, investment memo, competition, or modelling.
- Both equity workflows perform issuer identity verification before data collection and artifact creation. An unresolvable identity is a clarification result, not a partial report.
- Equity snapshot uses the public-source hierarchy: regulator, exchange, and issuer IR for issuer and financial facts; publicly verifiable quote sources for price and valuation anchors; issuer announcements before necessary credible-media supplementation. Search snippets are not evidence.
- Equity snapshot is constrained to a dated price, market scale or valuation anchor, latest financial summary, three to five direct company updates in a 30-day window, source timestamps, and data gaps. It excludes valuation, technical analysis, macro commentary, account data, Drive writes, and trading instructions.
- Deep equity research uses a fixed nine-chapter delivery: scope and core judgement; company and business model; industry and competition; management, governance, and capital allocation; financial performance and quality; expectations, catalysts, and tracking; valuation; risks, counter-thesis, and falsification; sources, timestamps, assumptions, and gaps.
- Financial-quality review uses four minimum cross-market checks: trend consistency across revenue, profit, and operating cash flow; cash conversion and accrual quality; receivables and deferred-revenue signals relative to revenue; and dilution/SBC, audit, and governance red flags. It reports evidence or a gap for each check and does not produce a letter grade.
- The deep valuation interface accepts only a source-traceable structured assumption set. A three-scenario DCF requires price, shares outstanding, net debt, WACC, terminal growth, and bear/base/bull free-cash-flow paths; reverse DCF additionally requires current free cash flow and forecast horizon. Missing required inputs leave the valuation chapter present but uncomputed with a clear gap.
- Deep research may state an auditable research judgement, valuation range, upside/downside risks, and falsification conditions. It must not state a buy/sell recommendation, position size, or trading action.
- All text-producing Skills create a uniquely named Markdown artifact under the active workspace’s `mars-research/` directory and never overwrite an existing artifact or write final research into the global Skill installation. PDF/PowerPoint rendering remains an explicit or materially useful extension.
- Technical analysis retains its deterministic yfinance-only evidence package and temporary chart, while moving long technical instructions into a one-level reference document to keep the default Skill context concise.
- Drive writeback continues to require separate explicit confirmation for initialization and archiving; its proposal and execution receipt are also local Markdown artifacts.

## Testing Decisions

- The highest and primary test seam is the collection-level offline verification entry point. It validates the externally observable package and artifact contract instead of coupling tests to internal implementation details.
- A good test asserts user-visible behavior: the installed runtime contains only required runtime material; each Skill exposes a coherent capability contract; local Markdown artifacts have the required sections; ambiguous identity blocks output; missing valuation inputs create a disclosed gap; and no artifact is overwritten.
- The collection-level verifier enforces the package budget of at most 60 files and 1 MiB, no prebuilt environment, no development-test references in runtime contracts, and no legacy installation surface.
- Deterministic offline fixtures exercise equity snapshot and deep research rendering. Each must produce a Markdown artifact in one second or less and must not require network, credentials, Drive, brokerage data, or browser interaction.
- Deep-research fixtures validate all nine chapter headings, all four financial-quality checks, the successful traceable DCF/reverse-DCF branch, and the missing-input valuation branch.
- Existing technical-analysis fixture tests remain the prior art for deterministic evidence, bad-data failure closure, temporary visualization behavior, and vendored chart-resource validation.
- A local Skills CLI integration check discovers exactly one root Skill and copies only the runtime package into a temporary project. An isolated locked dependency synchronization check confirms that technical-analysis dependencies remain available on demand without changing the installed runtime package.
- Performance evidence records the old local installation-stage baseline against the new local Skills CLI copy stage. Network registry and repository-fetch time are reported separately because they are external variables rather than deterministic package cost.

## Out of Scope

- Publishing branches, packages, tags, releases, deployments, or merging the v1.0.2 branch into `master`.
- Adding the full set of industry appendices, multiple extra valuation methods, Monte Carlo, EPV, EVA, position sizing, or a copy of the upstream reference Skill’s complete framework.
- Making Beneish M-Score or any market-specific forensic model part of the universal core.
- Providing direct trading recommendations, portfolio allocation, order entry, account access, brokerage data, private API keys, or background monitoring.
- Automatically generating PDF/PPT for every request, automatically archiving to Drive, or storing research in the global Skill installation directory.
- Replacing technical analysis’ yfinance-only data-source contract or adding hidden fallback providers.
- Treating network latency, npm registry availability, GitHub transfer time, or first-time Python download as a deterministic CI time budget.

## Further Notes

The implementation adopts the source hierarchy, artifact workspace, routing, deep-research scope, and performance
budgets already recorded in the project’s domain glossary and ADRs. It borrows the depth-first research discipline of
the referenced equity-research Skill while deliberately keeping the v1.0.2 universal core small. The user has
explicitly assigned v1.0.2 as the target version, but this specification does not authorize release publication or a
`master` merge.
