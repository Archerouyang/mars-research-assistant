# 1.0 Acceptance Plan

This document defines the acceptance plan for the first complete local Trading
Research Assistant workflow.

`1.0 = local trading research workflow`: a fresh Codex chat can guide the user
through the core trading research loop with the installed Skill, local runtime
views, fixture-backed checks, and read-only source boundaries. It is not a
public release tag and does not change Skill semantic versioning.

## Non-goals

- No broker write actions, including order placement, modification,
  cancellation, closing, or approval.
- No public release tag or public version semantics until the production chain
  and interaction model are confirmed.
- No KVN quantitative model construction, vendor selection, factor research, or
  backtesting inside this Skill.
- No option-flow anomaly vendor integration inside this 1.0 acceptance path.
- No real Codex trading-operation automations until the user confirms cadence,
  thread, timezone, runtime directory, allowed sources, broker permissions, and
  runtime write policy.
- No private broker records, private runtime files, screenshots, credentials,
  or paywalled research text in the public repository.

## Acceptance Prompts

Run these prompts in a fresh chat after Skill reinstall. The expected output
should be Chinese, concise, source-aware, and action-oriented.

| # | Prompt | Expected behavior |
| --- | --- | --- |
| 1 | `开始今天的交易研究` | Reads runtime health before analysis; reports `运行状态检查`, `券商来源健康`, `当前模式`, `宏观数据来源状态`, and missing confirmations; distinguishes real runtime state from repo fixtures; suggests the next Chinese workflow step. |
| 2 | `做本周交易计划 / 下周展望` | Uses Active Market Plan context, source routing, `macro-panel.json` status when available, macro/rates/policy/news events, current holding impact, and setup pool impact; explains any internal state labels before using them. |
| 3 | `更新今天盘前/盘中计划，检查计划内 setup` | Reads plan/update trail, macro panel status, and `intraday-watchlist.csv`; runs or mirrors `intraday_scan.py` behavior; prioritizes setup state changes, invalidations, approaching zones, and user decisions needed. |
| 4 | `看一下我的持仓` | After fresh explicit consent, reads the configured default broker and displays broker, symbol, quantity, latest price, market value, cost, unrealized P&L, cash, currency, and retrieval time. Missing factual fields remain `不可用`; no derived risk analysis is produced. |
| 5 | `做 DRAM/SOXX/QQQ 的滚动盘面分析` | Compares with prior analysis when available or states `本次作为基准分析`; labels main and auxiliary timeframes; lists support/resistance, add/trim zones, proportional sizing such as `1/5` or `1/3`, cost/buy-record context, and weekly event mapping. |
| 6 | `我刚下单了 / 这笔结束了，帮我复盘` | Runs the two-stage review flow: `post-order` asks entry reason, background, signal K, confidence, and risk plan; `post-exit` asks exit quality, mistakes, lessons, and result review; objective broker facts are read only when authorized. |
| 7 | `周末首次启动，先看看下周` | Reports `runtime_origin` and `startup_status`; when runtime is partial/uninitialized, 先给可用研究摘要 from current public/authorized non-account sources without writing runtime, then requests broker read-only, `ticker + trade_horizon + instrument`, and optional initialization. |

Additional cross-prompt behavior:

- Broker health keeps `unauthorized`, `available`, `partial_data`,
  `upstream_error`, `empty_positions_unverified`, and `needs_review` distinct.
- `portfolio_reconciliation` must be `not_confirmed` when IBKR is NAV-only and
  Longbridge has position detail; NAV is not merged into confirmed exposure.
- Authorized OHLCV for `medium-term swing` or position reassessment automatically
  includes a visible `PA Scenario Board`.
- Deep ticker research starts only after confirming
  `ticker + trade_horizon + instrument`; before that, only a watch-only summary
  is allowed.

## Exit Gates

Before claiming the local 1.0 workflow is ready, these gates must pass:

1. `bash scripts/verify-skill.sh`
2. `bash scripts/smoke-portable-skill-install.sh`
3. Reinstall the portable `mars-research-assistant` Skill through the documented
   skills workflow; no native wrapper or marketplace install is used.
4. Fresh-chat dry run of the Acceptance Prompts, with no private data copied
   into this repository.
5. Private forward test of Longbridge/IBKR read-only runtime views only after
   user authorization.

## Definition Of Complete

The local 1.0 workflow is complete when:

- all Exit Gates pass;
- each Acceptance Prompt returns a concise Chinese answer with a clear next
  step;
- the agent does not expose hidden quantitative model features as public Skill
  workflows;
- KVN is skipped or marked unavailable unless an external snapshot is provided;
- Longbridge macrodata is used only for macro/financial-condition values, not as
  a default news or broker-account source;
- broker data is read-only and normalized into standard runtime views before
  reports consume it;
- no private runtime or broker data is committed;
- the final `dev` branch is clean, verified, and ready for user-approved
  promotion to `master`.
