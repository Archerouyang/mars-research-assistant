# Drive 写入

同目录的 `capability.json` 定义本 Skill 的公开交付边界与离线验收场景。

```mars-skill-policy
{"delivery":"drive_writeback_with_local_receipt","forbidden_effects":["research","market_data","account_access","broker_write","trade_execution"]}
```

本 Skill 有两个公开操作：目录初始化，以及归档已经完成的研究成品。初始化不要求研究内容；
归档边界不变，只接收已经完成的研究成品。不要重新研究、取数、补全上游缺口、读取账户或执行
交易。若归档请求没有给出包含正文的完整研究成品，或无法判断其类型、日期/周次或主题，说明
缺口并停在提议前。

每次初始化提议、归档提议或执行结果先写为活动工作目录 `mars-research/` 中唯一的
`YYYY-MM-DD-drive-writeback[-NN].md`；绝不覆盖已有文件，也不在安装目录保存状态。该回执不
等于 Drive 写入：只有本 Skill 的独立确认规则满足后才能执行对应的 Drive 变更。

## 目录初始化

每次初始化都从 My Drive 根目录精确查找名为 `交易研究中心` 的文件夹。读取本次操作实际返回的
Drive ID，并只在本次提议与执行中锁定；不在本地持久化 Drive ID，不写入 Skill 安装目录、
隐藏缓存或配置文件。

- 未找到根目录时，提议创建完整骨架。
- 找到唯一根目录时，以该根目录 ID 为 parent 精确检查原生 Google Doc `总索引` 和六个分类
  文件夹，只提议缺失项。
- 找到多个同名根目录时停止，列出候选 Drive ID，请用户明确选择；不能猜测。

初始化提议必须展示完整目录树、已存在项、拟创建项、My Drive ID、锁定的目标 Drive ID、
唯一初始化 proposal ID 和尚未执行状态：

```text
交易研究中心/
├── 总索引（Google Doc）
├── 收件箱/
├── 每日市场思考/
├── 交易计划/
├── 专题研究/
├── 周度复盘/
└── 案例复盘/
```

确认必须明确回指初始化 proposal ID 及目标 Drive ID。含糊确认、其他 proposal ID 或其他目标
均无效。确认后先创建缺失根目录并锁定实际返回的 ID，再以真实 parent ID 创建缺失的六个目录；
六个目录齐全后才创建缺失的原生 Google Doc `总索引`。不通过名称路径拼接定位子项。

只补缺项；不移动、不覆盖、不重命名、不删除任何已有对象，也不预先创建日期、周次、专题、
案例或研究内容文档。创建后按 ID 读回并核对名称、MIME type 与 parent ID，再逐项报告
`created / existing / failed / pending`。Drive 不可用、权限不足、创建失败或读回失败时保留原因，
不声称成功；再次运行重新解析 My Drive，并只补仍缺失的项。结构完整时返回无变更成功，不创建
重复对象。

`总索引` 模板只包含交易研究中心说明、六个分类目录链接、交易计划/专题研究/周度复盘/
案例复盘四类索引、最近更新时间和数据缺口说明。初始化不扫描或回填历史文档；收件箱和
每日市场思考不逐条进入总索引。

## 研究归档

先根据研究类型提出目标位置、拟执行操作与是否更新总索引：

- **收件箱**：新建记录；不更新总索引。
- **每日市场思考**：更新日期对应文档中本次写入拥有的区段；不更新总索引。
- **交易计划、周度复盘**：更新周次对应文档中本次写入拥有的区段；更新总索引。
- **专题研究、案例复盘**：创建新文档；更新总索引。

将提议清楚展示给用户，包含目标位置、创建或更新、总索引动作和尚未执行的状态。没有明确的
写入确认时，绝不创建、更新或覆盖 Drive 文档。提议必须展示唯一标识；确认必须回指该标识及
目标。含糊的“可以”或与目标不相符的确认，继续要求澄清。

归档前也要从 My Drive 精确解析并锁定本次操作使用的交易研究中心及分类目录 Drive ID。若目录
尚未初始化，只展示目录初始化提议。初始化确认不能授权研究归档；初始化成功并读回验证后，
再展示具有不同 proposal ID 的归档提议并取得第二次明确确认。初始化成功后不得自动继续归档。

取得明确确认后，才使用可用的 Google Drive 工具执行该提议。新建时创建对应文档；更新时仅更新
本 Skill 明确拥有的区段，不静默替换整篇文档。写入后报告实际结果、目标与总索引是否更新。若
Google Drive 不可用或写入失败，保留失败原因且不要声称已写入。

## 投研工作台

工作台用于跨设备记录交易想法与已确认交易方案，不是研究 Markdown 的备份库。一个标的/投资
案例一个主文档，固定四区：交易想法日志、当前有效交易方案、证据与决策变更记录、复盘记录。
完整研报、估值 JSON、技术证据与 HTML 保留在本地，主文档只通过 artifact ID 或链接引用。

- 每个方案使用稳定 `plan_id` 和递增 `revision`，记录父版本、触发证据和变更原因。两个
  设备基于同一父 revision 各自修改时保留两条 revision，生成冲突摘要，要求用户选择保留、
  合并或另起方案，不按时间戳静默覆盖。
- 每次写入先展示目标文档、拟写入区段、`plan_id` 和 base revision，得到用户明确确认后才
  执行；Drive 不可用时写入可见的本地 outbox（状态“待同步”），重试前重新核对父 revision，
  不后台上传。
- 包内 `scripts/drive_workbench.py` 提供该合同的本地模拟（manifest、提议/回执/读取、
  冲突与 outbox），用于离线验证；它对真实 Drive 没有任何副作用，真实写入仍需上述确认
  纪律并读回核验。
